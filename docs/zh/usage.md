# 使用

**繁體中文** · [English](../en/usage.md)

本頁描述可重複的執行流程：第一個請求之前要做什麼、執行中應用在做什麼，以及
如何停止而不留下懸置 session。

## 起飛前檢查

- [ ] 這個帳號允許自動化閱讀（先問學校）。
- [ ] 檔案雜湊與 `SHA256SUMS` 相符。
- [ ] 目標務實：先試 `0.1`–`0.5` 小時，不要一開始就 `8`。
- [ ] 帳號正確。確認帳號卡上的姓名／電郵。
- [ ] 沒有其他客戶端同時對同一帳號執行。
- [ ] 整段執行期間裝置不會休眠或斷網。

## 登入

| 方式 | 網頁 | Android | Windows |
|---|:---:|:---:|:---:|
| Google 身分 | ✅ | ❌ | ✅ 本機登入頁 |
| 電郵 + 密碼 | ❌ | ✅ | ❌ |
| 驗證碼 | ✅ | ✅ | ✅ |
| 貼上 access token | ❌ | ❌ | ✅ |

登入結果是 access token，通常還有 refresh token。若回應只有 `ticket`，代表需要
第二因素：輸入寄到電郵的驗證碼。Ticket 是一次性的，會過期。

## 開始執行

1. 開啟應用並登入。
2. 確認配額卡顯示合理的總量（例如 `8.00 小時`）。
3. 設定**目標時數**（先從小開始）。
4. 心跳保持 `3` 秒、翻頁保持 `20` 秒，除非有理由更改。
5. 選用：勾選**模擬模式**一分鐘。計數器會動、日誌顯示模擬，但不發包。
6. 取消模擬，按**開始**。

應用會依序執行：

```text
GET  /v1/client/reading-time                 基準配額
GET  /v1/client/bookshelf/books?page=1&limit=50
GET  /v1/client/homepage                     書架少於 3 本時才用
GET  /v2/client/books/{id}                   書名、作者、章節
POST /v1/client/reading-time/start {bookId}  -> sessionId
POST /v1/client/reading-pos {bookId,pos}     初始估算位置
之後每秒 tick()：
  每 hbSec：  PATCH /reading-time {sessionId,time}
  每 turnSec：POST /reading-pos，並前進一頁
  每次 tick： 檢查目標／配額／錯誤次數
```

## 讀懂狀態

| 指示 | 意義 |
|---|---|
| `running` 狀態 | 排程器運作中 |
| 心跳圓點 | 心跳正在送出或剛完成 |
| 翻頁圓點 | 翻頁正在送出 |
| `net:` 狀態 | 最後一個請求路徑與結果 |
| 已用／總量 | 伺服器配額（**秒**），以小時顯示 |
| 已累積 | `max(本機回報秒數, 伺服器 used 差值)`，以小時顯示 |
| 剩餘 | 目標減去已累積 |
| 心跳／翻頁／書本數 | 本次執行的計數 |
| 錯誤 | 連續心跳失敗次數（上限 3） |

若伺服器與本機計數不一致，進度卡取較大值。這是刻意的，避免續期後顯示負進度。

## 停止條件

以下任一情況會自動停止：

| 條件 | 自動動作 |
|---|---|
| 達到目標 | `endBook()`、清除 timer |
| `usedQuota > totalQuota` | 以配額訊息停止 |
| 剩餘 ≤ 總量 20% | 日誌警告；可能繼續 |
| 連續 4 次心跳失敗 | 停止；對齊官方強制登出 |
| 手動停止後 `end` 失敗 | 記錄；仍清除本機 session |
| 書本讀完 | `end`，隨機換下一本 |
| 頁數用完 | 視為書本讀完 |

按**停止**可提前結束。應用送
`PATCH /v1/client/reading-time/end {sessionId}` 並清除 `sjrc.session`。直接關閉
分頁無法執行收尾；伺服器 session 會自行過期，但下次執行可能開新的。

## 日誌

日誌面板顯示時間、請求路徑、回應碼與錯誤。它不會刻意印出 token。分享前請：

1. 移除或遮蔽 `Bearer …`、`eyJ…`、ticket、session ID、電郵、學校名稱與書名。
2. 保留錯誤碼（`10102`、`80009`、`-777777`）與請求路徑。
3. 說明成品與版本。

網頁／Android 有**清空**但沒有匯出按鈕；需要保留就手動選取文字。Windows 的日誌
是唯讀文字框，規則相同。

## Windows 本機登入頁

Windows 版可開一個 loopback 頁面：

1. 按**開啟 Google 登入頁**。
2. 主頁監聽 `47821`，按 Google 登入時臨時監聽 `8080`（官方客戶端允許的
   origin）。
3. 登入後，登入頁把 Google 憑證換成 SJRC token，寫入桌面程式。
4. 成功後或閒置 2–3 分鐘後關閉服務。

若連接埠被佔用，改用**手動導入**：把 access token 貼進欄位，按**手動導入**。

## Android 生命週期

- 保持前景。WebView 計時器在背景會被節流。
- `onStop()` 呼叫 `__appPause()`，停止迴圈並要求結束 session。
- 系統可能殺掉程序。殘留 session 無害，但下次執行會開新的。
- 外殼沒有 Google 登入，請用電郵 + 密碼。

## 好習慣

- 每個帳號同時只跑一個客戶端。平行 session 會讓配額差值混亂，也可能觸發限流。
- 先做可驗證的短目標。成功跑完 0.1 小時再放大。
- 不要在網路切換期間執行；半開的請求看起來像失敗，會增加錯誤計數。
- 執行後檢查配額卡，那是唯一的真相來源。
- 共用機器要登出。Token 以明文存在瀏覽器儲存或登錄檔。

## 應用不會做的事

- 瀏覽器分頁關閉後不會繼續執行。
- 不會用同一個 `sessionId` 續接中斷的 session。
- 不會繞過配額、封禁、CAPTCHA 或強制改密碼。
- 不會隱藏有客戶端在呼叫 API；它送出與擷取到的官方客戶端相同標頭。
